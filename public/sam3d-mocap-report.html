EXECUTIVE SUMMARY

Bridging Raw Monocular Footage to Biomechanical Ground Truth

The SAM 3D Body Video Mocap project is a research-grade computer vision and kinematics pipeline designed to extract 3D human body and hand motion capture (mocap) from standard 2D monocular and multi-view video sequences.

The system couples Meta's SAM 3D Body (DINOv3) foundation model with SAM 3 promptable video segmentation, MoGe metric depth estimation, and the Rerun interactive 3D spatial visualization engine. It bridges raw video footage to biomechanically accurate 3D meshes (18,439 vertices) and hierarchical skeleton kinematic models (127 joints), providing export formats compatible with Nokov, OpenSim, and Blender.

01 // SYSTEM ARCHITECTURE

5-Stage Kinematics Pipeline & Data Flow

The project is structured into three processing stages with dedicated memory management for constrained GPU environments (e.g., 8GB VRAM). The data flows deterministically from video frames to multi-format kinematic deliverables:

STAGE 1

Input Modalities

• Raw RGB Video (.mp4 / .avi / .mov)
• Text Prompts (e.g., 'person')
• Interactive 2D Point Clicks
• Model Checkpoints (DINOv3, MHR, SAM3, MoGe)

STAGE 2

Tracking & Segmentation

• ViTDet / SAM3 Human Detection
• Zero-shot Multi-Object Tracking
• Point-Prompted Prop Masking
• CPU Detector Offloading

STAGE 3

3D Body Estimation

• SAM 3D Body (DINOv3 Backbone)
• MHR Forward Kinematics (127 Joints)
• 18,439-Vertex Surface Meshes
• MoGe Dense Metric Depth

STAGE 4

Temporal Smoothing

• Savitzky-Golay (Savgol) Polynomials
• Preserves Athletic Velocity Spikes
• Gaussian Filtering for Organic Walk
• Foot Contact Ground Clamping

STAGE 5

Outputs & Downstream

• Rendered Mocap Overlay Video
• Interactive Rerun 3D Stream (.rrd)
• Nokov 127-Joint Biomech CSVs
• OpenSim & Blender Skeletal Rigs

02 // INPUT SPECIFICATIONS

Inputs, Prompts & Foundation Models

2.1 Primary Video & Prompt Inputs

  • Video Media: Standard monocular video files (.mp4, .avi, .mov) recorded at 24–60 fps. Multi-view inputs are supported via multi-camera image folders or .rrd recordings (e.g., HoCap dataset).
  • Text Prompts: Zero-shot prompts (e.g. --text "person") fed to SAM3 video tracking for autonomous athlete bounding.
  • Interactive Point Clicks: Point-Video-Segment mode (process_video_pvs_multiobj.py) to track persons and handheld objects (such as bats or hockey sticks) simultaneously.

2.2 Model Weights & Checkpoints

  • SAM 3D Body (DINOv3): facebook/sam-3d-body-dinov3 backbone and regression heads estimating 3D camera translation, mesh vertices, and MHR joints.
  • MHR Kinematic Model: assets/mhr_model.pt containing Meta Human Representation parametric skeleton definitions.
  • SAM 3 Video Tracker: facebook/sam3 sequential multi-object and promptable segmentation engine.
  • MoGe V1 Depth Predictor: Monocular metric/relative depth model for background/foreground 3D scene point clouds.

03 // DELIVERABLES & TELEMETRY

Outputs, Data Structures & Research CSVs

3.1 Visual & Interactive Outputs

Output Artifact Description Destination
Rendered Video (.mp4) Source video overlaid with 3D shaded body mesh, joint skeleton, and camera trajectory. output_dir/<video_name>_mocap.mp4
Interactive Rerun Canvas (.rrd) Synchronized 2D video viewport alongside a 3D orbital viewport featuring shaded meshes, camera frustum, and dense depth point clouds. Streamed live or saved to .rrd
Kinematic Plots (.png) Multi-axis plots of joint coordinates (e.g., left/right wrist punches in boxing) across time and 3D trajectory traces. output_dir/<video_name>_trajectories.png

3.2 Raw Data Dumps (.pickle, .npz, .json)

Each frame records a structured telemetry dictionary for every detected individual:

pred_vertices: (18439, 3) float32 # Dense 3D surface mesh pred_keypoints_3d: (70, 3) float32 # MHR70 landmark format pred_keypoints_2d: (70, 2) float32 # Projected image pixels pred_joint_coords: (127, 3) float32 # All 127 anatomical joints pred_global_rots: (127, 3, 3) # Global rotation matrices body_pose_params / hand_pose_params # Latent posture vectors pred_cam_t: [tx, ty, tz] # Camera translation focal_length: 1042.5 px # Camera focal length bbox: [x1, y1, x2, y2, conf] # 2D detection box

3.3 Research-Grade CSV Exports

Implemented in boxing_fullbody_mocap_export.py and export_mocap_complete.py:

  • <video>_keypoints_3d.csv: Frame-by-frame 3D metric coordinates (x_m, y_m, z_m) for 70 landmarks.
  • <video>_joints_positions.csv: Metric coordinates for all 127 SMPL-X/MHR skeletal bones.
  • <video>_rotations_quaternion.csv: Normalized orientation quaternions (qw, qx, qy, qz) per joint for Nokov, OpenSim, and Blender rigs.
  • <video>_rotations_euler.csv: Rotation angles expressed in Euler degrees (XYZ convention).
  • <video>_camera_params.csv: Camera translation offsets and focal length per frame.
  • <video>_metadata.csv: Per-frame timestamps and bounding boxes.

Pipeline Components & Code Organization

sam-3d-body-video-mocap/ ├── video_mocap_pipeline.py # Unified CLI pipeline ├── rerun_visualizer.py # Rerun SDK 2D/3D viewer ├── depth_estimator.py # MoGe metric depth map │ ├── process_boxing_views.py # Multi-panel combat rendering ├── boxing_fullbody_mocap_export.py # Nokov-compatible 127-joint CSV ├── analyze_hockey_multiobj.py # Dual-entity athlete + stick ├── process_video_pvs_multiobj.py # Point-prompted SAM3 tracker ├── process_video_sam3_pcs_seq.py # Text-prompted with VRAM unload │ ├── sam-3d-body/ # Meta SAM 3D Body (DINOv3 + MHR) │ ├── sam_3d_body/ # Estimator, models, renderers │ └── notebook/ # Setup utilities & helpers │ └── sam3d-body-rerun/ # Pixi env, Gradio UI, multi-view ├── tool/demo_mv_body.py # Multi-view MHR optimization ├── tool/demo_chunk_video.py # Memory-efficient video chunking └── src/sam3d_body/ # Package modules

Key Software Modules

  • VideoMotionCapture: Core engine handling video decoding, model inference, temporal smoothing, data serialization, and video re-encoding.
  • TemporalSmoother: Multi-method temporal filter:
    • Gaussian Filtering: Default for organic walking and conversation.
    • Savitzky-Golay (Savgol): Polynomial filtering preserving velocity peaks during high-speed actions (punches, athletic jumping).
    • Moving Average: Fast linear smoothing.
  • demo_mv_body.py: Differentiable multi-view optimization fusing multiple camera angles via 2D keypoint triangulation and L1 reprojection losses.

05 // HARDWARE TUNING

Memory Strategies for Constrained GPUs (8GB VRAM)

CPU Detector Offloading

In video_mocap_pipeline.py, if VRAM is < 12 GB, the 2D detector (ViTDet) automatically offloads to CPU, conserving all GPU memory for the heavy SAM 3D Body foundation model.

Sequential Stage Pipeline

Scripts like process_video_sam3_pcs_sequential.py run SAM3 video tracking first, export mask tracks to disk, call torch.cuda.empty_cache() and gc.collect(), then instantiate SAM 3D Body.

Chunking & Streaming

In sam3d-body-rerun, demo_chunk_video.py and demo_stream.py process long videos in small overlapping blocks or frame-by-frame with constant O(1) GPU memory usage.
